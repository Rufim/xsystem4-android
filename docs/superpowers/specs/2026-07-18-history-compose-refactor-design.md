# История сообщений + перевод UI на Compose + модульная структура

Дата: 2026-07-18
Статус: дизайн

## Цель

1. **История сообщений**: кнопка «История» в боковой панели → полноэкранный
   скролл-список последних **50** сообщений с **именем говорившего**.
2. **Перевод всего интерфейса приложения на Jetpack Compose** (включая лаунчер
   и экраны лицензий).
3. **Разбить код по модулям** (пакетам) и причесать: EngineActivity сейчас —
   «бог-объект» с UI, настройками и связкой TTS.

## 1. История сообщений

### Источник данных
Тот же поток, что питает TTS: `NativeBridge.onAdvText` (+ `onAdvPage`).
Разбор имени говорившего — существующая логика TTS (`TtsSegmenter.speakerOf`,
маркер `【Имя】` в System 4; накопление `pendingSpeaker` до текста реплики).
Для System 3.x бокс приходит целиком без маркера — поле говорившего пустое.

**Изменение в нативных мостах (оба движка):** сейчас `bridge_emit` гейтится
`tts_enabled` — история должна наполняться и при выключенной озвучке, поэтому
гейт из нативного emit убирается; решение «озвучивать или нет» остаётся в
Kotlin (`TtsSpeaker.speak` уже проверяет `enabled`). Страничный фильтр
System 3.x (бой/меню) стоит до emit и продолжает работать — мусор в историю
не попадает.

### Модель
`MessageHistory` — синглтон процесса движка: кольцевой буфер на 50 записей
`HistoryEntry(speaker: String?, text: String, timeMs: Long)`, потокобезопасный,
`StateFlow<List<HistoryEntry>>` для Compose.

### UI
Полноэкранный Compose-экран: `LazyColumn`, автопрокрутка к последнему,
имя говорившего — акцентным цветом над текстом реплики, тёмная тема в стиле
текущих диалогов. Кнопка «назад» — стрелка, как в остальных экранах.

## 2. Compose

- **Стек:** Kotlin 1.7.20 → **2.0.x** + плагин `org.jetbrains.kotlin.plugin.compose`,
  Compose BOM, `activity-compose`. AGP 8.7.3 и Gradle 8.14 остаются.
- **Лаунчер** (`LauncherActivity` → `ComponentActivity` + Compose): список игр
  (иконка+имя, клик — запуск, лонг-тап — удаление), меню (обновить, установить
  из ZIP, помощь, лицензии), прогресс установки. Экраны лицензий — Compose.
- **Оверлей игры:** SDL-активити — не `ComponentActivity`, поэтому Compose
  подключается через `ComposeView` с вручную привязанными
  `ViewTreeLifecycleOwner`/`SavedStateRegistryOwner` (utility `ComposeOverlay`,
  один на проект). Все полноэкранные экраны поверх игры — Compose:
  **История**, **Читы**, **Настройки TTS**.
- **Боковая панель** (ручка + кнопки) — тоже Compose через тот же оверлей.

## 3. Структура пакетов (`io.github.rufim.alice`)

| Пакет | Содержимое |
|---|---|
| `bridge` | `NativeBridge` (JNI, колбэки движков) |
| `tts` | `TtsSpeaker`, `TtsSegmenter`, `NameTranslator` |
| `history` | `MessageHistory`, `HistoryScreen` |
| `cheats` | `CheatRepository` (данные/скан), `CheatsScreen` |
| `engine` | `EngineActivity` (тонкая: SDL + связка), `XSystem4Activity`, `XSystem35Activity`, `EnginePanel` (Compose-панель), `TtsSettingsScreen` |
| `launcher` | `LauncherActivity`, `GameList`/`Engine`/установка, `PEResourceExtractor` |
| `ui` | тема (цвета/типографика), `ComposeOverlay`, общие компоненты (шапка со стрелкой, поля, свитчи) |

`EngineActivity` после рефакторинга: создать SDL, панель, связать
`NativeBridge → TtsSpeaker + MessageHistory`, применить сохранённые настройки.
Вся отрисовка экранов — в Compose-файлах пакетов.

Настройки остаются в `SharedPreferences` (`bridge_prefs`) — ключи не меняются,
поведение (включая движко-зависимые поля фильтров System 3.x) сохраняется.

## Не меняется

- Нативные движки (кроме снятия TTS-гейта с emit), JNI-имена, авто-листание,
  читы-механика, определение движка, процессы `:engine4`/`:engine35`.
- Функциональность текущих экранов — переносится 1:1 на Compose (включая
  ML Kit-перевод имён в читах и фильтры страниц/окон только для System 3.x).

## Риски

- Kotlin 1.7 → 2.0: возможны мелкие правки синтаксиса/зависимостей
  (coroutines, ML Kit совместимы).
- `ComposeView` поверх SDL-поверхности: следить за фокусом/инпутом (оверлей
  перехватывает касания только когда открыт).
- Рост APK на ~2–3 МБ (Compose runtime).
