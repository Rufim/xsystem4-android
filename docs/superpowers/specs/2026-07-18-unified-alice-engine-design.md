# Единое приложение для xsystem4 + xsystem35 (System 4 и System 3.x)

Дата: 2026-07-18
Статус: дизайн утверждён, ожидается ревью спеки

## Цель

Собрать **одно** Android-приложение, запускающее игры AliceSoft на двух движках:

- **xsystem4** — System 4 (напр. Daiteikoku), уже с готовыми фичами TTS/читы/авто-листание.
- **xsystem35** — System 3.x, включая System 3.9 (напр. Daiakuji).

Для xsystem35 требуется **полный паритет фич**: TTS-озвучка ADV-текста, читы (просмотр/скан/правка переменных VM), авто-листание при авто-режиме. Личное использование (коммерческие игры, APK не распространяется).

## Подход

**База — существующий репозиторий `xsystem4-android`** (ветка `tts-cheats`), в него прицепляется xsystem35 вторым нативным движком. Причина: вся полировка фич (TtsSpeaker, CheatPanel, ML Kit-перевод имён, диалоги, drawables) уже готова здесь; переделывать её на базе xsystem35-sdl2 было бы дороже.

applicationId делаем новым (напр. `io.github.rufim.alice`), чтобы приложение не конфликтовало с уже установленным одиночным xsystem4 на телефоне.

## Архитектура процессов

Причина изоляции — **не параллельность** (игры всегда запускаются по одной), а чистая переинициализация нативной части. Внутри одного процесса SDL и движок не сбрасываются надёжно: раз загруженная `libxsystemN.so` остаётся резидентной (`dlopen`), глобальное состояние SDL не обнуляется, поэтому последовательный запуск другого движка в том же процессе глючит. Свой процесс на движок = гарантированно чистый старт при каждом запуске.

Два класса активити нужны по чисто технической причине: `android:process` задаётся статически на каждую `<activity>` в манифесте, поэтому для назначения разных процессов двум движкам нужны две записи. (SDLActivity и так завершает процесс при выходе из игры; свести к одной активити теоретически можно, но изоляция по процессам надёжнее — финально решается при реализации.)

Каждая игровая активити живёт в **своём процессе** через `android:process`:

| Активити | Процесс | Нативные библиотеки |
|---|---|---|
| `LauncherActivity` | главный | — |
| `XSystem4Activity` | `:engine4` | `libSDL2.so`, `libxsystem4.so` |
| `XSystem35Activity` | `:engine35` | `libSDL2.so`, `libxsystem35.so` |

Каждый запуск игры — свежий процесс движка → чистое состояние SDL.

**Определение движка** по содержимому папки игры:
- `System39.ain` присутствует → System 3.x → `XSystem35Activity`.
- `System40.ini` или `AliceStart.ini` присутствует → System 4 → `XSystem4Activity`.

## Компоненты

### Общий Kotlin (движко-независимый, переиспользуется как есть)

- `TtsSpeaker`, `TtsSegmenter` — очередь TTS, автоязык по сегментам, имя говорящего при смене, приглушение музыки, авто-листание.
- `CheatPanel`, `EdgePanel`, `NameTranslator` (ML Kit JA→RU), drawables, диалоги TTS/читов.
- `NativeBridge` — единый объект с `external`-функциями. Оба движка экспортируют **одинаковые JNI-символы** (C-часть под нашим контролем; каноническое имя класса моста фиксируем один раз для обоих движков).
- `abstract EngineActivity : SDLActivity` — вся обвязка боковой панели TTS/читов и колбэков моста. Подклассы отличаются лишь `getLibraries()` / `getArguments()` и движко-специфичными диалогами.

### XSystem4Activity

Текущее поведение без изменений (наследует `EngineActivity`).

### XSystem35Activity

Наследует `EngineActivity` + движко-специфика xsystem35: `inputString`/`inputNumber`-диалоги, MIDI-плеер, `-gamedir`/`-savedir` аргументы. Портируется из `GameActivity.kt` xsystem35-sdl2.

### Лаунчер / библиотека игр

Единый `GameList`, определяющий движок по маркер-файлам (см. выше) и хранящий его в `Item`. Клик по игре открывает соответствующую активити. Установка/удаление/иконки поддерживают оба формата (System 4 — `.ini`+иконка из PE; System 3.x — маркеры System39/установка из архива).

## Нативная часть xsystem35

### TTS
В `texthook.c` добавить Android-режим по образцу готового Emscripten-режима: `texthook_message` / `texthook_newline` / `texthook_nextpage` / `texthook_keywait` → JNI-колбэки. Точки перехвата уже встроены в движок (вызываются из `message.c` и `input.c`), путь отрисовки патчить не нужно.

### Читы
API поверх `variable.c`: имена переменных `v_name()` (из `System39.ain`), доступ `v_ref()`, строковые `svar_get/svar_set`. Реализует браузер имён, скан по значению (Cheat-Engine-стиль) и запись — теми же нативами, что уже есть в NativeBridge.

### Мост / JNI
Отдельный `android_bridge` в дереве xsystem35, экспортирующий те же нативные методы, что и общий `NativeBridge`.

### Авто-листание и модалки
Синтетический тап работает (SDLActivity). Логику «не пропускать модальное уведомление» настраиваем под xsystem35 отдельно: у него другой путь отрисовки, но есть чистый сигнал `texthook_keywait`, который можно использовать вместо glyph-count-эвристики из System 4.

## Сборка

Один Gradle-модуль, один верхнеуровневый `CMakeLists.txt` с `add_subdirectory` для обоих движков → две `.so`. Исходники движков подключаются как git-сабмодули/поддеревья.

**Риск SDL2.** Обоим движкам нужен `libSDL2.so`. Если версии SDL2 разойдутся — конфликт по имени файла в `jniLibs`. На этапе реализации сверить версии SDL2 обоих движков и выровнять на общую (обе — порты kichikuou на SDL2, вероятно совместимы).

## Явные допущения

- Полный паритет фич TTS/читы/авто-листание для обоих движков.
- Одно приложение, один значок, новый applicationId.
- Формат хранения игр — как в текущих лаунчерах (`getExternalFilesDirs`, подпапка на игру).

## Открытые вопросы (решаются при реализации)

1. Точная версия SDL2 для каждого движка и стратегия выравнивания.
2. Формат имени говорящего в ADV System 3.9 у Daiakuji (в Daiteikoku — `【Имя】`; сегментатор обрабатывает обобщённо, но нужно проверить на реальном тексте).
3. Нужна ли модалко-защита авто-листания в xsystem35 (проверить на игре).

## Порядок работ (высокоуровнево)

1. Каркас единого проекта на базе xsystem4-android: подключить xsystem35 сабмодулем, собрать `libxsystem35.so`, выровнять SDL2.
2. Рефакторинг общего Kotlin в `EngineActivity` + два подкласса; единый `NativeBridge`.
3. Единый лаунчер с определением движка.
4. Нативные хуки xsystem35: texthook Android-режим, cheat API, android_bridge/JNI.
5. Настройка TTS/авто-листания/модалок под xsystem35.
6. Сборка APK, установка на телефон, проверка на Daiakuji и Daiteikoku.
