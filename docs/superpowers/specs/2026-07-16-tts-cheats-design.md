# TTS-озвучка и окно читов для xsystem4-android

Дата: 2026-07-16. Статус: дизайн согласован с пользователем.

## Цель

Личная сборка xsystem4-android (тест-игра: русифицированная Daiteikoku) получает две
возможности:

1. **TTS**: автоматическое чтение всего текста ADV-диалогов встроенным Android
   TextToSpeech, с автоопределением языка реплики и заглушением штатной голосовой
   озвучки игры на время работы TTS.
2. **Читы**: панель просмотра и редактирования глобальных переменных System 4 VM
   (деньги, параметры персонажей) — браузер по именам плюс итеративный поиск по
   значению в стиле Cheat Engine, с опциональным переводом японских имён переменных
   через Google ML Kit.

Вход в обе функции — боковая панель, выезжающая по тапу/свайпу от тонкой
полупрозрачной «ручки» у края экрана.

## Архитектура

Три слоя, изменения в двух репозиториях (xsystem4-android + submodule xsystem4):

```
┌─ Kotlin (project/app) ──────────────────────────────┐
│ EdgePanel (ручка + drawer)                          │
│  ├─ вкладка TTS: переключатель, статус              │
│  └─ вкладка Читы: фильтр по имени, скан по          │
│     значению, редактирование, ML Kit перевод        │
│ TtsSpeaker: TextToSpeech + очередь + автоязык       │
└──────────────┬────────────────▲─────────────────────┘
   JNI: natives│(читы, mute)    │callback onAdvText()
┌──────────────▼────────────────┴─────────────────────┐
│ C: android_bridge.c (только Android-сборка)         │
│  ├─ хук в AnteaterADVEngine (текст ADV, голос)      │
│  ├─ mute голосового микшера / каналов               │
│  └─ доступ к глобалам VM: список/чтение/запись/скан │
└─────────────────────────────────────────────────────┘
```

### Слой движка (C, xsystem4)

Новый файл `src/android_bridge.c` (условная компиляция под Android; на прочих
платформах — пусто либо консольная заглушка для тестов на Linux).

**Хук текста.** В `src/hll/AnteaterADVEngine.c` в `ADVLogList_AddText`,
`ADVLogList_AddNewLine`, `ADVLogList_AddNewPage`, `ADVLogList_AddVoice` добавляются
вызовы тонких функций-нотификаторов (`adv_bridge_on_text(struct string*)` и т.п.,
no-op вне Android). Мост накапливает строку до конца логической строки/страницы,
конвертирует SJIS→UTF-8 (`sjis2utf` из libsys4) и отдаёт в Kotlin вместе с флагом
«у реплики есть штатный голос» (был ли `AddVoice` для этой строки).

**Имя говорящего.** На живых данных Daiteikoku проверяется, отличимо ли имя
(отдельный вызов, префикс страницы или иной канал). Если да — мост передаёт имя
отдельным полем, Kotlin озвучивает его только при смене говорящего. Если надёжного
источника нет — имена не озвучиваются, остальное не страдает (риск принят).

**Заглушение голоса.** Основной путь: у System 4 микшеры именованные — найти
голосовой (`Voice`) и ставить громкость 0 при включённом TTS, восстанавливать при
выключении. Запасной путь (если голос Daiteikoku не выделен в отдельный микшер):
глушить конкретные каналы, через которые проигрываются voice-файлы. Выбор пути —
эмпирически на этапе реализации.
РЕЗУЛЬТАТ ПРОВЕРКИ (2026-07-16, Linux): микшеры Daiteikoku — マスター/ＢＧＭ/効果音/
音声/女性/男性; глушатся 音声+女性+男性 (mute), работает.

**Приглушение музыки (дополнение по итогам проверки).** Опция «приглушать музыку
при чтении»: на время фразы TTS громкость BGM-микшера (ＢＧＭ/bgm) опускается до
настраиваемого уровня (по умолчанию 15% от исходной), после фразы
восстанавливается (`bridge_duck_music(bool, percent)`; Kotlin дёргает её из
UtteranceProgressListener onStart/onDone). Уровень — ползунок в панели,
сохраняется в настройках.

**Доступ к переменным VM.** API моста поверх глобальной страницы VM и метаданных
`ain->globals`:
- `bridge_list_globals(filter_utf8)` → массив {id, имя UTF-8, тип, значение} —
  только скалярные int/bool/float и int-элементы массивов/структур;
- `bridge_read(loc)` / `bridge_write(loc, value)` — loc = (страница, слот);
- `bridge_scan(value, mode)` — mode = new|narrow: первый скан обходит глобальную
  страницу рекурсивно (массивы, структуры) и запоминает совпавшие локации;
  narrow перечитывает список кандидатов и оставляет совпавшие с новым значением.

Потокобезопасность: чтения и одиночные int-записи выполняются без остановки VM
(для личного чит-инструмента гонки приемлемы; страницы VM могут реаллоцироваться,
поэтому скан хранит локации, а не сырые указатели, и перечитывает через
проверку границ).

### JNI-мост

- Движок → Kotlin: `onAdvText(text: String, speaker: String?, hasVoice: Boolean)`
  через `SDL_AndroidGetJNIEnv()` (поток VM аттачится один раз).
- Kotlin → движок: `external fun`-функции читов и `setVoiceMuted(Boolean)`,
  регистрируются из `android_bridge.c`.

### Слой приложения (Kotlin)

**EdgePanel.** Обычные View поверх SDL-поверхности в `XSystem4Activity` (разрешения
не нужны). Ручка: полупрозрачная полоска ~4×48 dp у правого края. Тап/свайп —
выезжает drawer с вкладками «TTS» и «Читы»; тап вне панели закрывает её. Состояние
(вкл/выкл TTS, включённость перевода имён) — в SharedPreferences.

**TtsSpeaker.** Обёртка над `android.speech.tts.TextToSpeech`. Очередь реплик
(QUEUE_ADD; при явном пропуске страницы игроком очередь очищается — flush).
Автоязык по символам сегмента: кириллица → ru, кана/кандзи → ja, иначе → en;
голос переключается `setLanguage` перед `speak`. Имя говорящего произносится
только при смене. При включении TTS вызывается `setVoiceMuted(true)`, при
выключении — восстановление.

**Вкладка читов.** Список (RecyclerView): имя (или перевод), тип, текущее значение,
редактирование по тапу (диалог с числовым полем). Режимы:
- фильтр по имени (подстрока, по оригиналу и по переводу);
- скан по значению: поле ввода + кнопки «Новый поиск» / «Сузить» / «Сброс», счётчик
  кандидатов; список показывает кандидатов, когда их ≤ ~500.

**Перевод имён (опция).** Google ML Kit on-device Translation (unbundled),
JA→RU через EN-пивот. Модели скачиваются при первом включении переключателя;
результаты кэшируются в памяти (map имя→перевод), UI не блокируется (перевод
асинхронный, ячейка обновляется по готовности). Если модель недоступна (нет сети,
нет Google-сервисов на прошивке) — переключатель отключается с пояснением; всё
остальное работает.

## Поток данных TTS

1. VM (поток SDL) исполняет сцену → `ADVLogList_AddText(...)` → хук моста.
2. Мост копит сегменты; `AddNewLine`/`AddNewPage` завершает строку → SJIS→UTF-8 →
   JNI `onAdvText(text, speaker?, hasVoice)`.
3. `TtsSpeaker` режет текст на языковые сегменты, ставит в очередь, говорит.
4. Штатный голос молчит, т.к. голосовой микшер заглушен на время TTS.

## Обработка ошибок

- TTS не инициализировался / нет RU-голоса → тумблер TTS выключается с тостом.
- Модель ML Kit не скачалась → переключатель перевода недоступен, тост с причиной.
- Запись в переменную вне диапазона типа → кламп и отображение фактического значения.
- Любой сбой моста не должен ронять игру: все JNI-вызовы обёрнуты в проверки,
  хуки no-op при выключенных функциях.

## Тестирование

- **Linux-сборка движка**: заглушка моста пишет ADV-текст в консоль — проверка
  хуков и полноты текста на реальной игре; API читов дёргается тестовой утилитой
  (список/скан/запись) с проверкой против отладчика движка.
- **Устройство**: TTS на стартовой сцене Daiteikoku (RU-текст, JP-вставки),
  проверка заглушения голоса; читы — найти деньги сканом (значение из игрового UI),
  изменить, убедиться в игре.
- Milestone 1 = TTS, Milestone 2 = читы; фичи независимы, каждая проверяется отдельно.

## Риски (приняты)

1. Имя говорящего может не течь через ADV-лог → имена не озвучиваем.
2. Голос может не быть отдельным микшером → запасной путь с каналами.
3. Скан по значению находит ложные ячейки → итеративное сужение.
4. ML Kit требует скачивания модели с серверов Google → опция деградирует мягко.
5. Правка чужих переменных может сломать сейв → пользователь предупреждён, это
   личный инструмент; бэкапы сейвов лежат в `<game>/SaveData`.
